RTL Support

Markup+ automatically detects right-to-left languages and adjusts the entire document layout. No special syntax required — write Persian, Arabic, Hebrew, or Urdu normally and Markup+ handles the rest.

Language-agnostic

RTL detection is part of the Markup+ language itself, not a specific implementation. It works identically in JavaScript, Python, and the CLI.

How it works

When rendering a document, Markup+ scans the text for RTL characters. Based on the ratio of RTL to LTR characters, it decides the document direction:

RTL characters Result
Less than 30%LTR (left-to-right)
30% or moreRTL (right-to-left)

The 30% threshold handles mixed content where a mostly-English document has a Persian title, or vice versa.

When to force direction

Case Solution
Persian document with English code examples Auto-detect usually works — code stays LTR
English document with Persian title Auto-detect may fail — use --ltr
Persian content under 30% threshold Force with --rtl
Bilingual document (equal mix) Force based on primary audience
Persian document with no Latin characters Auto-detect works perfectly

  • Code blocks stay left-aligned (LTR)
  • URLs and emails stay LTR
  • Numbers display correctly
  • Latin words inline with Persian text render naturally

What changes in RTL mode

When RTL is detected, these CSS properties change automatically:

Element LTR RTL
Text direction direction: ltr direction: rtl
Text alignment text-align: left text-align: right
List bullets Left side Right side
Blockquote border border-left border-right
Table alignment Left-aligned cells Right-aligned cells
Code blocks direction: ltr direction: ltr (unchanged)
Font family Inter, system Vazirmatn, Tahoma, system
HTML attribute dir="ltr" dir="rtl"

RTL fonts

When RTL is detected, Markup+ uses a Persian-friendly font stack:

  1. Vazirmatn — modern Persian font
  2. Tahoma — widely available on Windows
  3. Arial — universal fallback
  4. System default sans-serif

Common issues

Problem Cause Fix
RTL not activating Less than 30% RTL characters Force with direction: 'rtl'
Code blocks appear RTL Wrong CSS override Don't override pre or code direction
Numbers render wrong Mixed Arabic-Indic vs Latin digits Use one digit system consistently
Punctuation misplaced Bidirectional text edge case Force direction explicitly
URLs appear reversed Rare browser issue Wrap in <span dir="ltr">
Fonts not Persian Vazirmatn not loaded Include font from Google Fonts

Best practices

  1. Let auto-detect work for pure Persian/Arabic/Hebrew content
  2. Force direction for mixed or ambiguous documents
  3. Test with real content, not just "سلام"
  4. Use consistent digit system — either ۱۲۳ or 123
  5. Don't override code block direction — it should always be LTR
  6. Load Vazirmatn font for professional Persian typography
  7. Check URLs and emails after RTL rendering
Unicode-based detection

Markup+ uses Python's unicodedata.bidirectional() and its JS equivalent to classify characters. It recognizes R, AL, and AN bidirectional classes as RTL. This means it works for any RTL script, not just the common ones.
