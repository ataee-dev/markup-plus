Building a Chatbot

Use renderFragment to render rich Markup+ responses inside a chat interface. Fragments are scoped so they don't interfere with the host page's CSS.

Why fragments for chat?

Chatbot responses need rich formatting — code, tables, lists, links. renderFragment produces scoped HTML that won't break your chat UI's styles.

Why scoping matters

Without scoped: true, the fragment's CSS would leak into your page and break your chat UI. With scoping:

Option Effect Use case
scoped: true All CSS is prefixed with a unique class Embedding in existing pages (recommended)
scoped: false CSS is included as-is (may conflict) Full control over the page

Best practices

  1. Always use scoped: true when embedding in existing pages
  2. Enable includeScripts: true if responses contain tabs or collapsible sections
  3. Enable includeCDNScripts: true if responses contain code blocks, math, or charts
  4. Cache the CDN scripts — don't reload Prism/KaTeX on every message
  5. Sanitize user input before passing to Markup+ (prevent injection)
  6. Test with real LLM output — it may generate unexpected syntax
  7. Limit fragment size — large responses can slow down the UI
  8. Use theme option to match your chat UI's colors

Security considerations

Important

Markup+ does not sanitize user input. If you render user-generated MUP, you must sanitize it first to prevent XSS. Use a sanitizer like DOMPurify around the rendered output.

Common issues

Problem Cause Fix
Fragment breaks chat UI Missing scoped: true Add scoped: true to options
Code blocks unformatted Prism not loaded Add includeCDNScripts: true
Tabs don't work Scripts not loaded Add includeScripts: true
Slow rendering Large fragments or CDN reloads Cache scripts, split responses
XSS vulnerability Unsanitized user input Sanitize before rendering
